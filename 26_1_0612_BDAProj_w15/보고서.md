## 1. 문제 정의

본 프로젝트는 얼굴 이미지 한 장을 입력받아 이미지 제작 과정에 AI가 활용되었을 가능성이 있는지 판별하는 Streamlit 서비스를 만드는 것을 목표로 합니다. 다만 이 데이터는 영상 기반 탐지 데이터라기보다, URL 출처상 실사 사진과 생성형/아바타 이미지가 구분되는 이미지 데이터에 가깝기 때문에 “AI 활용 이미지 판별” 문제로 정의하는 것이 적절합니다.

## 2. 데이터 소개 & EDA

- 데이터 규모: 6,557행 × 17열
- 데이터 형식: CSV 메타데이터 + `image_url` 기반 원격 이미지
- 타깃 컬럼: `label` (`FAKE`, `REAL`)
- 주요 주의점: `category`, `source`, `fake_method`, `detection_difficulty`는 라벨과 강하게 연결될 수 있어 모델 입력에서 제외합니다.

EDA에서는 라벨 분포, 이미지 품질 분포, `confidence_score` 분포, URL 도메인 편향, 누수 가능 컬럼과 라벨의 관계를 확인합니다.

## 3. 특성 엔지니어링

이미지 자체를 모델에 넣는 사전학습 모델 방식을 사용하지만, 데이터 이해와 품질 점검을 위해 다음 파생 정보를 활용합니다.

- URL 도메인 추출
- 이미지 해상도
- 종횡비
- 평균 밝기
- 선명도
- 얼굴 검출/크롭 보조 정보

도메인, source, fake_method 등은 모델 성능을 부풀릴 수 있는 누수성 정보이므로 분석용으로만 사용합니다.

전처리와 특징추출 흐름은 다음 순서로 구성했습니다.

1. `FINAL_DATASET.csv` 메타데이터 로드 및 필수 컬럼 확인
2. `image_url` 기반 이미지 다운로드 및 로컬 캐시 저장
3. 이미지 품질 검사(해상도, 밝기, 선명도, 열기 실패 여부)
4. 선택적으로 얼굴 검출 및 얼굴 영역 크롭
5. 기본 이미지 특징추출
6. `features_sample_*.csv` 또는 `features_all.*`로 저장

| 특징 | 의미 | 사용 목적 |
|---|---|---|
| `brightness` | 평균 밝기 | 저조도/과노출 이미지 점검 |
| `sharpness` | 선명도 | 흐린 이미지 감지 |
| `face_area_ratio` | 이미지 내 얼굴 영역 비율 | 얼굴 중심 이미지 여부 확인 |
| `mean_pixel`, `std_pixel` | 전체 픽셀 평균/표준편차 | 이미지 질감·대비 차이 확인 |
| `meta_total_pixels` | 메타데이터 기준 해상도 | 라벨별 이미지 크기 편향 확인 |
| `domain` | URL 도메인 | 출처 편향과 누수 분석 전용 |

특징추출 결과는 EDA 페이지에서 소규모 샘플로 생성할 수 있고, 터미널에서는 다음 명령으로 배치 추출할 수 있습니다.

```bash
cd ai_image_detection_app
python -m src.feature_pipeline --out data/features_all.parquet --chunk 500 --workers 8 --limit 1000 --quality-check --face-crop
```

## 4. 모델 / 서비스

모델 서비스는 HuggingFace 사전학습 이미지 분류 pipeline을 사용합니다. 사용자가 이미지를 업로드하거나 URL을 입력하면, 앱은 이미지 품질을 먼저 점검한 뒤 모델 예측 결과를 `FAKE/REAL`, 확률, 신뢰도 구간으로 표시합니다.

샘플 성능 평가 기능도 추가했습니다. `FINAL_DATASET.csv`에서 일부 샘플을 선택하고, 각 이미지 URL을 다운로드한 뒤 모델 예측과 실제 라벨을 비교합니다. 평가 결과로 accuracy, confusion matrix, 클래스별 요약, 오분류 사례를 확인할 수 있습니다.

단, 이 평가는 전체 데이터 성능이 아니라 네트워크 상태와 샘플 수에 영향을 받는 소규모 점검 결과입니다.

추가로 4GB/8GB GPU 제약을 고려해 경량 학습 방식을 도입했습니다. 대형 모델 전체를 파인튜닝하지 않고, ResNet18, MobileNetV3, EfficientNet-B0 같은 사전학습 CNN에서 이미지 임베딩을 추출한 뒤 Logistic Regression 또는 RandomForest로 `FAKE/REAL`을 학습합니다. 이 방식은 GPU 메모리 부담이 작고, CPU에서도 작은 샘플 기준으로 실행 가능하며, 사전학습 모델 단독 추론과 데이터셋 맞춤형 경량 모델을 비교할 수 있다는 장점이 있습니다.

| 방식 | 입력 | 학습 여부 | 장점 | 한계 |
|---|---|---|---|---|
| HuggingFace 사전학습 모델 | 이미지 | 추가 학습 없음 | 바로 서비스 가능 | 현재 데이터 도메인과 맞지 않을 수 있음 |
| Handcrafted 특징 + Logistic Regression | 밝기, 선명도, RGB 통계 등 | 학습 | 원리 설명이 쉬움 | 표현력이 제한적 |
| CNN 임베딩 + Logistic Regression | ResNet18/MobileNetV3 임베딩 | 학습 | 4GB GPU에서도 실행 가능 | 임베딩 모델에 의존 |
| CNN 임베딩 + RandomForest | CNN 임베딩 | 학습 | 비선형 관계 일부 반영 | 데이터가 적으면 과적합 가능 |

개인 PC 4GB GPU에서는 `resnet18` 또는 `mobilenet_v3_small`, batch size 4를 권장하고, 학교 PC 8GB GPU에서는 `efficientnet_b0`, batch size 8 이상을 시도할 수 있습니다.

## 6. 결론 & 한계

이 프로젝트를 통해 URL 기반 얼굴 이미지 데이터에서 실사 이미지와 생성/아바타 계열 이미지의 차이를 탐색하고, 사전학습 모델을 이용한 간단한 판별 서비스를 구현했습니다.

주요 한계는 다음과 같습니다.

- 실제 영상 기반 탐지 문제가 아니라 이미지 기반 AI 활용 가능성 판별에 가깝습니다.
- 이미지 URL 만료, 다운로드 실패, 외부 서버 차단 가능성이 있습니다.
- REAL/FAKE의 출처 도메인이 다르면 모델이 이미지 내용보다 데이터 출처 편향에 영향을 받을 수 있습니다.
- 사전학습 모델을 그대로 사용했기 때문에 해당 데이터 도메인에 완전히 최적화되었다고 보기 어렵습니다.
- 샘플 성능 평가는 전체 성능을 대표하지 않으므로 보고서에는 샘플 수와 실패 수를 함께 기록해야 합니다.

향후 개선 방향은 로컬 검증용 이미지셋 구축, ViT 파인튜닝, CLIP/EfficientNet 비교, Grad-CAM 또는 attention 기반 설명 추가입니다.
