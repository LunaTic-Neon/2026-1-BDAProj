# AI 활용 이미지 판별 프로젝트

- **이름 / 학번**: 박성준 / 20242887
- **데이터 출처 / 라이선스**: Kaggle — Deepfake Detection Dataset 2026

## 1. 문제 정의

본 프로젝트의 목표는 얼굴 이미지 한 장을 보고 해당 이미지의 제작 과정에 AI가 활용되었을 가능성이 있는지 판별하는 Streamlit 서비스를 만드는 것이다. 다만 이 데이터는 일반적인 영상 기반 딥페이크 탐지보다, URL 출처 기준으로 실사 사진과 생성형/아바타 이미지가 함께 포함된 구조에 가깝다. 따라서 본 프로젝트에서는 이를 “AI 활용 이미지 판별” 문제로 정의하였다.

예측 대상은 `label` 컬럼(`FAKE`, `REAL`)이며, 입력은 메타데이터가 아니라 이미지 자체이다. `category`, `source`, `fake_method`, `detection_difficulty`처럼 라벨과 직접 연결될 수 있는 컬럼은 모델 입력에서 제외했다.

## 2. 데이터 소개 & EDA

- 데이터 규모: 6,557행 × 17열
- 데이터 형식: CSV 메타데이터 + `image_url` 기반 원격 이미지
- 타깃 컬럼: `label` (`FAKE`, `REAL`)

EDA에서는 다음 내용을 확인했다.

1. **라벨 분포**  
   `FAKE`가 `REAL`보다 조금 많은 약한 불균형 구조이다.

2. **데이터 품질**  
   `image_quality`, `confidence_score`, `dataset_split` 분포를 확인해 데이터 상태를 점검했다.

3. **누수 가능 컬럼**  
   `category`, `source`, `fake_method`, `detection_difficulty`는 라벨과 강하게 연결될 수 있어 모델 입력에서 제외했다.

4. **샘플 이미지**  
   실사 사진과 생성형/아바타 이미지의 시각적 차이를 직접 확인했다.

5. **결측치**  
   일부 메타 컬럼의 결측 비율은 높지만, 이 데이터는 URL과 메타데이터가 함께 제공되는 구조이므로 일부 결측이 곧바로 전체 품질 저하를 의미하지는 않는다.

처리 원칙은 다음과 같다.
- `image_url`이 없는 행은 이미지 기반 분석에서 제외
- 누수 가능 컬럼은 모델 입력에서 제외
- 다운로드 실패나 품질이 낮은 이미지는 결과 해석 시 별도로 고려

## 3. 특성 엔지니어링

본 프로젝트는 이미지 자체를 입력으로 사용하지만, 데이터 이해와 추가학습 모델 구성을 위해 몇 가지 파생 정보를 활용했다.

- URL 도메인(`domain`) 추출
- 해상도, 종횡비 분리
- 평균 밝기(`brightness`)
- 선명도(`sharpness`)

이 중 `domain` 같은 정보는 모델 입력이 아니라 데이터 편향과 누수 가능성을 설명하는 데 사용했다.

또한 현재 모델·서비스 페이지에서는 사전학습 CNN(`resnet18`)에서 이미지 임베딩을 추출한 뒤, 그 임베딩을 입력으로 하는 경량 분류기를 연결하는 구조를 사용한다. 즉, 대형 모델을 처음부터 다시 학습하는 대신, 사전학습 모델의 특징 벡터를 활용해 우리 데이터에 맞게 추가학습하는 방식이다.

## 4. 모델 / 서비스

본 프로젝트는 **사전학습 CNN + 경량 추가학습 모델** 방식을 사용한다.

- 사전학습 CNN이 이미지에서 임베딩 추출
- 추가학습 분류기가 `FAKE/REAL` 예측
- 필요 시 외부 사전학습 이미지 분류 모델을 fallback으로 사용

입력 → 출력 흐름은 다음과 같다.
1. 사용자가 이미지 파일을 업로드하거나 데모 샘플을 선택한다.
2. 앱이 해상도, 밝기, 선명도, 종횡비를 점검한다.
3. `resnet18`에서 이미지 임베딩을 추출한다.
4. 경량 분류기가 `FAKE/REAL`을 예측한다.
5. 최종 판정, 예측 확률, 간단한 성능 지표를 화면에 표시한다.

샘플 성능 평가는 `FINAL_DATASET.csv`에서 일부 샘플을 선택해 실제 라벨과 예측 결과를 비교하는 방식으로 수행한다. 결과로는 Accuracy, 클래스별 요약, Confusion Matrix, 오분류 사례를 확인할 수 있다.

현재는 추가학습 구조는 구현되어 있지만, 저장된 모델의 학습 규모가 충분하지 않아 성능이 낮을 수 있다. 따라서 현 단계에서는 “구조 구현과 원리 설명”에는 적합하지만, 성능 자체는 향후 재학습이 필요하다.

## 5. Streamlit 앱

앱은 세 페이지로 구성된다.

1. **EDA**: 라벨 분포, 데이터 품질, 누수 가능 컬럼, 샘플 이미지, 결측치 요약
2. **시각화**: 라벨 분포, 품질 분포, 출처 도메인 편향, 누수 가능 컬럼 진단
3. **모델·서비스**: 단일 이미지 판별과 샘플 성능 평가

실행 방법:

```bash
cd ai_image_detection_app
pip install -r requirements.txt
streamlit run app.py
```

화면 캡처에는 다음 내용을 넣으면 된다.
- EDA: 라벨 분포, 샘플 이미지, 결측치 요약
- 시각화: 도메인 편향, 누수 가능 컬럼 진단
- 모델·서비스: 단일 이미지 판별 결과, 확률 그래프, 샘플 성능 평가 결과

## 6. 결론 & 한계

본 프로젝트를 통해 URL 기반 얼굴 이미지 데이터에서 실사 사진과 생성형/아바타 이미지의 차이를 탐색하고, 이를 바탕으로 AI 활용 가능성을 판별하는 서비스를 구현했다. 특히 사전학습 CNN 임베딩에 우리 데이터 기반 경량 추가학습 모델을 연결하는 구조를 구현했다는 점이 의미 있다.

한계는 다음과 같다.
1. 이 데이터는 일반적인 영상 기반 딥페이크 탐지보다, 실사 사진과 생성형/아바타 이미지 구분 문제에 더 가깝다.
2. `image_url` 기반 데이터이므로 다운로드 실패나 URL 만료 문제가 발생할 수 있다.
3. `source`, `domain` 등 출처 편향이 커서 모델이 얼굴 자체보다 제작 환경 차이를 학습할 가능성이 있다.
4. 현재 추가학습 모델은 구조는 구현되었지만, 충분히 재학습되지 않아 성능이 낮을 수 있다.
5. 샘플 성능 평가는 전체 데이터셋 성능을 대표하지 않는다.

향후에는 더 많은 샘플로 임베딩을 다시 추출해 경량 모델을 재학습하고, 다운로드 성공률이 높은 검증용 로컬 이미지셋을 구축해 성능을 보완할 수 있다.
