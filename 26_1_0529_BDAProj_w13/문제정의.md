# 프로젝트 문제정의

> 1차 작업 산출물 — **이미지가 AI 합성(FAKE)인지 실제 사진(REAL)인지 판별하는 서비스**

--- 

## 1. 선택한 데이터

| 항목 | 내용 |
|------|------|
| 이름 | Deepfake Detection Dataset 2026 (`FINAL_DATASET.csv`) |
| 출처 | Kaggle (보고서에 데이터셋 URL 명시 예정) |
| 크기 | **6,557행 × 17열** |
| 형식 | CSV (메타데이터) — **이미지는 `image_url`로만 제공 → 직접 다운로드 필요** |

**주요 컬럼**

- `label` (**타깃**): `FAKE` 3,767 / `REAL` 2,790 — 약한 불균형(57:43)
- `image_url`: 모델에 넣을 실제 이미지 주소 (중복·결측 없음)
- 그 외: `gender`, `age_group`, `image_quality`, `confidence_score`(0.80~0.99) 등 메타정보

> ⚠️ **데이터 누수 주의**: `category`·`source`·`fake_method`·`detection_difficulty`는 `label`과 거의 1:1로 대응합니다. 학습에 쓰면 정확도 100%가 나오지만 의미가 없으므로 **EDA 분석용으로만** 사용합니다.

---

## 2. 풀고 싶은 문제

> **"얼굴 이미지 한 장을 보고, AI가 만든 가짜(FAKE)인지 실제 사진(REAL)인지 자동 분류한다."**

- **타깃**: `label` (FAKE / REAL) — **이진 분류**
- **입력**: 메타데이터가 아닌 **이미지 픽셀 자체** (누수 컬럼 배제)

---

## 3. 만들 서비스 (완성 모습)

**사용자가 얼굴 이미지를 업로드 → FAKE/REAL 판정 + 확신 확률(%) 표시**

- **기술**: 사전학습 **ViT pipeline** (파인튜닝 없이 사용, 13주차 `03_pretrained_vit.ipynb` 방식)
- **MVP 기준**: 이미지 입력 → ViT 예측 → Streamlit 화면 표시. 이것부터 동작시킨 뒤 정확도·시각화 보강
- (여유 시) LLM/Ollama로 판정 근거 한 줄 해설 추가

**앱 구조** (가이드 권장 멀티페이지 템플릿, 이미지 데이터용)

```
pages/1_EDA.py        # 라벨 분포·결측·메타 분석
pages/2_시각화.py      # 클래스/난이도/품질별 그래프
pages/3_모델_서비스.py  # 이미지 업로드 → 예측 → 결과
src/data_loader.py    # CSV 적재 + image_url 다운로드 (@st.cache_data)
```

---

## 4. 예상 난관

**이미지가 픽셀이 아니라 `image_url`(원격 주소)로만 제공된다.**

→ 전부 받으면 느리고 URL 만료 위험. **대응**: 개발 시 일부만(`nrows`) 사용 + 다운로드 캐싱·타임아웃 처리 + 데모용 샘플 수십 장 미리 저장.

**데이터의 본질적 한계** (보고서에 명시): URL 도메인 분석 결과 REAL은 Unsplash 실사 사진, FAKE는 dicebear·multiavatar 등 아바타 생성 API였습니다. 따라서 "정교한 딥페이크 탐지"보다 **"실사 vs AI 합성 이미지 구분"** 과제로 보는 것이 정확합니다.
