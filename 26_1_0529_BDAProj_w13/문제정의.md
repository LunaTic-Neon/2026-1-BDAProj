## 1. 선택한 데이터

- **이름**: Deepfake Detection Dataset 2026 (`FINAL_DATASET.csv`)
- **출처(URL)**: Kaggle — Deepfake Detection Dataset 2026
- **라이선스**: Kaggle 데이터셋 공개 라이선스 (제출 보고서에 데이터셋 페이지 URL 명시 예정)
- **크기**: **6,557행 × 17열**
- **형식**: CSV (메타데이터 표) + **이미지는 `image_url` 컬럼의 원격 URL로 제공** -> 픽셀 데이터는 직접 다운로드해야 함
- **어떻게 받았나**: Kaggle에서 직접 다운로드 (`FINAL_DATASET.csv`)

| 컬럼 | 설명 | 비고 |

## 2. 풀고 싶은 문제

- **한 문장으로**: "**딥페이크 이미지 데이터로**, 주어진 얼굴 이미지가 **AI가 생성한 가짜(FAKE)인지 실제 사진(REAL)인지**를 **자동으로 분류**하고 싶다."
- **예측/분류 대상(target)**: **있음 → `label` (FAKE / REAL) 이진 분류**
- **클래스 분포**: FAKE 3,767건(57.5%) / REAL 2,790건(42.5%) → 약한 불균형 (별도 처리 없이 진행 가능, 필요 시 가중치 고려)

### ⚠️ 핵심 주의사항 — 데이터 누수(Data Leakage)

EDA에서 확인한 결과, 아래 메타데이터 컬럼들은 `label`과 **거의 100% 대응**합니다.

- `category` (AI Generated↔FAKE, Authentic↔REAL)
- `source` (MultiSource↔FAKE, Unsplash↔REAL)
- `fake_method` (StyleGAN3↔FAKE, 결측↔REAL)
- `detection_difficulty` (Easy는 전부 REAL)

→ **이 컬럼들을 학습 입력(feature)으로 쓰면 정확도 100%가 나오지만 의미가 없습니다.**
→ 따라서 본 프로젝트는 **메타데이터가 아니라 `image_url`로 받은 이미지 픽셀 자체**를 보고 판별하는 것을 목표로 합니다. (위 누수 컬럼들은 EDA·시각화 분석 용도로만 사용)

## 3. 만들 서비스 (완성 모습)

- **사용자가 무엇을 입력하면 → 무엇을 보여주는 앱인가**:
  사용자가 **얼굴 이미지 파일을 업로드(또는 URL 입력)** 하면 → 앱이 **"FAKE(AI 생성) / REAL(실제)" 판정 결과와 확신 확률(%)**, 그리고 간단한 근거 설명을 화면에 보여줍니다.
- **사용할 기술**: **딥러닝(사전학습)** — 가이드 3의 이미지 경로(**사전학습 ViT pipeline**, 파인튜닝 없이 사용). 13주차 `03_pretrained_vit.ipynb`에서 실습한 방식을 그대로 적용.
  - (선택 보강) 판정 결과에 **LLM/Ollama로 자연어 해설** 한 줄 붙이기 — 시간이 남으면 진행.

### 앱 구조 (가이드 권장 템플릿 — 이미지 데이터용)

### 합격 기준 (최소 동작)

사용자가 이미지를 입력 → 사전학습 ViT가 FAKE/REAL 결과 반환 → Streamlit 화면에 표시. **이것부터 동작시킨 뒤** 정확도·시각화를 보강합니다.

## 4. 예상 난관 1가지

**가장 큰 난관: 이미지가 CSV에 픽셀이 아니라 `image_url`(원격 주소)로만 들어 있다.**

- 6,557개 이미지를 전부 받으면 시간·네트워크 부담이 크고, URL이 만료되거나 응답이 느릴 수 있습니다.
- **대응 방안**:
  1. 개발 단계에서는 `nrows`로 일부만 받아 파이프라인을 먼저 완성 (가이드 FAQ 권장).
  2. 다운로드 함수에 캐싱(`@st.cache_data`)·타임아웃·실패 시 건너뛰기 처리.
  3. 데모용 샘플 이미지 수십 장을 미리 받아 `data/`에 저장해 두고 발표 시 사용.

### (추가로 인지한 한계)

EDA 중 `image_url` 도메인을 분석한 결과, 데이터셋이 엄밀한 "딥페이크 영상 프레임"이라기보다 **출처가 다른 이미지의 조합**임을 확인했습니다.

- **REAL**: `images.unsplash.com` (실제 인물 사진, 2,790장)
- **FAKE**: `api.dicebear.com`(2,499) · `api.multiavatar.com`(1,000) — 만화/도형풍 아바타, `randomuser.me`(198) · `i.pravatar.cc`(70) — 실사풍 아바타

즉 `fake_method`에 `StyleGAN3`로 기재되어 있으나 실제 URL은 아바타 생성 API들입니다. 따라서 본 모델은 "정교한 딥페이크 탐지"보다 **"실사 사진 vs AI 생성/합성 이미지 구분"** 과제로 정의하는 것이 정확하며, 이 점을 한계로 명시하겠습니다.
